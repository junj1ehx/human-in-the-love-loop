# Agent 系统架构

## 设计

这是“人工做决定、工具维护状态、AI 提供有限建议”的系统，不是自动驾驶。

```text
本人真实输入
   │
   ├─ 隐私门：去标识、拒绝原始聊天/联系方式
   │
   ├─ 阶段状态机：matched → conversing → date_planned → dating
   │                                      → exclusive → relationship
   │
   ├─ 专项教练（按需调用）
   │    ├─ 资料审阅
   │    ├─ 消息压力/真实性检查
   │    ├─ 约会计划与安全检查
   │    └─ 复盘与单变量实验
   │
   └─ 本人批准、本人改写、本人行动
```

## 模块职责

### Intake / 自我模型

只处理使用者自己的目标、现实和边界。输出资料素材和待澄清问题。

### Profile Coach

检查事实、具体性、隐私和线下可兑现性。不生成虚假兴趣、AI 图片或夸张身份。

### Matching Coach

区分先验、明示事实、未知和脑补。输出投入优先级分、置信度、值得验证的问题和反证；分数表示时间投入价值，不表示人的价值。

### Funnel Optimizer

跟踪审核资料、触达、匹配、首回、实质对话、邀约、初约、双向二约和排他关系。每个迭代周期只改一个瓶颈变量。

### Conversation Coach

先要求本人写意图和草稿；只指出负担、压力、歧义和不像本人的地方。默认不输出可直接发送的完整成品。

### Date Planner

围绕双方兴趣生成公开、适中、可退出的选项，检查时间、地点、交通、费用和同意。

### Safety Gate

对金钱、投资、账户、陌生 App、身份矛盾、强迫、跟踪和不尊重边界做优先拦截。高风险时停止其他优化。

### Reviewer

用阶段、事件和自评找一个当前瓶颈。不能诊断对方，也不能把拒绝归因于星座、性别或民族。

## 为什么没有“自动回复 Agent”

自动回复会把关系建立在代理人格上，扩大隐私处理，且把对方的同意建立在错误作者身份上。系统宁可降低短期回复率，也不制造线上线下人格断裂。

## 投入优先级分如何使用

系统可以使用 100 分投入优先级，用于决定有限时间和有限触达机会投到哪里。硬性冲突和安全门在总分之外，不能被外貌、学历或其他分数抵消。分数应在累积足够触达样本后用真实转化率校准。
